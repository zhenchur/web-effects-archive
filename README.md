## Просмотр эффектов

Архив — белая страница с навигацией и последовательными секциями. Над каждым демо расположен номер: «Эффект 1», «Эффект 2» и далее по мере пополнения архива. Анимации управляются обычной прокруткой страницы: при движении вниз эффекты проходят вперёд, при движении вверх — назад.

Прокрутку колёсиком и переходы навигации сглаживает Lenis (`lerp: 0.1`). Эффекты обновляются по фактической позиции страницы в том же кадре. Сенсорная прокрутка остаётся нативной; при системном уменьшении движения сглаживание отключается. Lenis подключён только к странице архива и не входит в переносимый модуль.

На странице нет панели настроек, вкладок, автопроигрывания, ползунка прогресса или сохранения пресетов. Параметры задаются в коде подключения; описание и инструкции переноса находятся в документации модуля.

## Запуск

Node.js 24.12.0 или совместимая версия Node 24.

```sh
git clone https://github.com/zhenchur/web-effects-archive.git
cd web-effects-archive
npm ci
npm run dev
```

Открыть http://127.0.0.1:4191/web-effects-archive/ . Страница Эйлера использует другой порт, 4190.

```sh
npm test
npm run build
npm run preview
```

## Cinema Letters

Смена слов с пространственным поворотом и stagger по буквам. Сохранены модель Cinema 4D, ось за плоскостью, компенсирующие повороты, кривая `.838, 0, .162, 1` и фейд перед поворотом ребром. Геометрия и алгоритм движения перенесены из рабочей версии Эйлера без оптимизации.

Текущая последовательность: **Made by → Google → Gemini → Android → Pixel**, stagger **4%**, слева направо. Шрифт наследуется от проекта; коммерческие шрифты и изображения Эйлера в репозиторий не входят.

Модуль не зависит от приложения архива, React, меню, хранилища настроек или Lenis. Единственная runtime-зависимость — GSAP. Прогресс задаётся через `setProgress(0…1)`, поэтому хост может использовать прокрутку, таймлайн или ползунок. Документация по API и пример React находятся в папке эффекта.

ZIP по ссылке выше содержит исходники TypeScript, стили, README и готовое самостоятельное демо со встроенным GSAP. Для запуска скачанного демо: распаковать, выполнить `npm install` и `npm run dev`. В составе архива есть и собранный JavaScript для использования без TypeScript.

## Fresh Content

Текстовый барабан с типографикой из [Figma, node 3799:717](https://www.figma.com/design/v5LtS1JVmKmytVHVtQphks/oskar?node-id=3799-717&t=teZGz3IYR176aW92-1) и движением по [референсу Pinterest](https://ru.pinterest.com/pin/794603928044403424/). Строки **Fresh / Content / from / Mexico / City / to the / World** поднимаются от нижней границы вьюпорта, увеличиваются к центру, затем уменьшаются у верхней границы. Они остаются непрозрачными и выходят за края без затухания. Соседние строковые блоки имеют общие границы без дополнительного промежутка, `line-height` — `.9`. Максимальный кегль синхронизирован с «Эффектом 1», минимальный составляет 16% от него; насыщенность обоих эффектов — 600.

Фраза проходит три раза; дополнительные визуальные копии заполняют края барабана. Сцена закреплена от верхней границы на всю высоту вьюпорта, заголовок и прозрачная навигация находятся поверх неё. Прокрутка вверх разворачивает движение. При уменьшенном движении остаётся один статичный список без закрепления; скринридер также читает фразу один раз.

Переносимый модуль `createFreshContent(host, options?)` возвращает методы `setProgress(0…1)`, `refresh()` и `destroy()`. Свой список строк, число проходов и reduced motion задаются в `options`. Единственная runtime-зависимость — GSAP: `quickSetter` меняет `fontSize` и `top`, чтобы браузер рисовал буквы при текущем кегле. CSS-масштабирование и повороты не используются. Модуль измеряет DOM только при обновлении геометрии, без замеров в кадрах прокрутки. Изменение кегля требует layout и paint; частота кадров зависит от устройства и стоимости отрисовки текста.

Прокрутку и закрепление сцены обеспечивает интеграция; модуль не импортирует Lenis или код архива. [Документация и пример подключения](effects/fresh-content/README.md) находятся рядом с исходниками. Сборка создаёт `public/downloads/fresh-content.zip`, а также отдельные `fresh-content.js` и `fresh-content.css`; ZIP включает самостоятельное демо со встроенным GSAP и нативной прокруткой без элементов управления.

Стили пробуют использовать TT Neoris Variable через CSS `local()`, однако браузер может не распознать установленный шрифт. Для точного совпадения принимающий проект подключает лицензированный WOFF2 через `@font-face` и задаёт семейство переменной `--fc-font-family` на хосте. Без такого подключения доступен резервный шрифт.

Для локальной проверки архива можно сохранить шрифт и CSS с `@font-face` в игнорируемой папке `.local/`, а в `.env.local` задать `LOCAL_PREVIEW_STYLE_URL=/web-effects-archive/.local/preview.css`, затем перезапустить `npm run dev`. Vite подключает этот CSS только в режиме разработки. Коммерческие шрифты не входят в Git, production-сборку или ZIP. Подробный пример — в [документации Fresh Content](effects/fresh-content/README.md#шрифт).

## Film Cards

Два варианта coverflow-галереи по [референсу Motion Gallery: Film](https://motion.dev/examples/react-gallery-film). В «Эффекте 3» карточки переключаются перетаскиванием, кликом или стрелками клавиатуры; «Эффект 4» проходит ту же последовательность при прокрутке закреплённой секции. Обратное движение возвращает предыдущие состояния. При reduced motion оба варианта показывают статичную сетку.

Модуль `effects/film-cards/` независим от архива и Motion+: CSS 3D, GSAP, локальные фотографии с указанными источниками. [API, интеграция и ограничения](effects/film-cards/README.md). ZIP содержит оба самостоятельных демо, исходники и изображения.

## Структура

```text
effects/cinema-letters/   независимый модуль, стили и документация
effects/fresh-content/    текстовый барабан, стили и документация
effects/film-cards/       карточная галерея: drag/click и scroll
src/registry.ts          каталог эффектов
src/main.ts             последовательные демо и привязка к прокрутке
src/style.css           белая страница, навигация и секции эффектов
examples/               самостоятельный пример из ZIP
tests/                  контроль сохранения модели Cinema 4D
scripts/                упаковка эффекта и публикация GitHub Pages
```

## Добавление эффекта

1. Создать `effects/<id>/` с независимым модулем, стилями и README. Не импортировать код из `src/` или другого исходного проекта.
2. Добавить запись в `src/registry.ts` и подключить следующую секцию с заголовком «Эффект N». Сохранить непрерывную прокрутку между секциями. Название модели, версию, параметры и способ переноса описать в документации модуля.
3. Добавить упаковку нового модуля в `scripts/package-effect.mjs` и необходимую проверку поведения.
4. Проверить демо, обратное движение, маленький экран и режим уменьшенного движения.
5. Зафиксировать изменения и опубликовать. Изменения принятого характера движения выпускать как новую версию; сохранять прежние параметры и модель.

## Публикация на GitHub Pages

Исходники хранятся в `main`; собранный сайт и ZIP — в `gh-pages`. В настройках GitHub Pages выбран **Deploy from a branch → gh-pages → /(root)**.

```sh
git add .
git commit -m "Add or update effect"
git push origin main
npm run deploy
```

Команда запускает проверки и сборку, затем публикует `dist` через отдельную временную копию Git. Она проверяет, что исходники сохранены и отправлены в `main`, и записывает их SHA в `deployment.json`. Форсированная отправка не используется. Для публикации нужны права записи в репозиторий; обычный просмотр демо авторизации не требует.

Папки `node_modules`, `dist`, `qa` и собранные загрузки не коммитятся в `main`: они воспроизводятся из исходников и lockfile. GitHub Pages получает готовые загрузки вместе с сайтом.

## Проверено и ограничения

Математика эффекта сверяется с числовыми замерами исходной сцены Cinema 4D. При системной настройке reduced motion слова показываются обычным статическим списком. Фактическая производительность зависит от устройства, длины слов и количества букв; специальная оптимизация модели пока не проводилась.

Буквы разделяются по Unicode code points, как в исходном эффекте. Для составных emoji, комбинируемых диакритических знаков и сложных письменностей потребуется отдельная адаптация разбивки. В исходниках нет трекинга, ключей доступа и серверной части.
